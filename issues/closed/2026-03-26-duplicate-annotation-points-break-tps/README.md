# 重複アノテーション点が TPS を破綻させる件

更新日: 2026-03-26

## 同梱資料

- `LAJ_017_LAJ_015.json`: 調査時点で `_local/` に退避していた 015 の参考アノテーション
- `LAJ_017_LAJ_144.json`: 調査時点で `_local/` に退避していた 144 の参考アノテーション

## 結論

- `015` と `144` の異常表示は、`overlay` の座標計算バグというよりアノテーション側の重複点が主因
- 特に `144` は完全重複点 1 件で TPS が数値的に破綻し、生成結果が爆発した
- 再生成時の RMSE 確認で異常検知できており、品質管理として有効だった

## 調査結果

### LAJ_015

- 以前の重複点が問題だった可能性が高い
- 現行データでは重複なし
- アフィン近似の誤差は小さく、現時点では大きな構造破綻は見えない

### LAJ_144

- `overlay/data/LAJ_017_LAJ_144.json` に同一対応点の重複が存在した
- 同じ `base(6863,3263) -> overlay(6884,3271)` が 2 回入っていた
- この状態では TPS 自己 RMSE が `5675.51px` まで悪化
- 生成された `144-mapping*.tsv` も画像外へ大きく飛ぶ値になった
- 重複 1 件だけを除いて試すと、TPS 自己 RMSE はほぼ 0 に戻った

## メモ

- 完全重複点は TPS で特に危険
- `Space` 長押しによる二重記録が発生源の可能性が高い
- そのため `overlay.html` の記録は `keydown` ではなく `keyup` に変更済み
- 必要になったら、生成前に完全重複点を自動除去する対策も検討する
